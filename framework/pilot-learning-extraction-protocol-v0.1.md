# Pilot Learning Extraction Protocol v0.1

A pilot is incomplete until useful discoveries are extracted from the project into reusable framework assets.

## Three destinations
1. Knowledge Base — observations, evidence, examples, references.
2. Framework — reusable rules, gates, schemas and algorithms.
3. Skill candidate — executable instructions/tool workflow, only after the rule has survived project evidence.

## Extraction loop
Finding → project evidence → generalizable hypothesis → counterexample check → framework rule → pilot validation → versioned promotion.

## Required pilot outputs
- discovery findings;
- false-positive/false-completion findings;
- rules added/changed;
- rules rejected;
- tool limitations;
- autonomy failures;
- SPEC-BLOCKER examples;
- assurance defects found by execution;
- reusable schemas/checklists;
- Skill delta candidates.

## Anti-pattern
A project improvement that is not evaluated for reusable learning is implementation work, not a framework pilot.
